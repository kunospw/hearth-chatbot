2 · Interaction behaviour

Resume in one tap. The Continue card is one InkWell. A chat reopens at the newest message, in the mode that chat was last in (stored per conversation).
Continue vs. recent characters. Continue = conversations (title + last line, opens the chat). Recent characters = people (round avatars, open the profile). Each section has a one-line subtitle saying which.
Chat ↔ Story keeps your place. Before switching, record the first visible message id and how far into it you'd scrolled (0–1). After the new layout, scroll to that message plus the same fraction. If you were at the bottom, stay at the bottom.
Streaming never steals scroll. Follow new text only when within 72 dp of the bottom; otherwise show “New reply below”. Don't re-scroll on every chunk; throttle rebuilds to ~60 ms.
Keyboard. resizeToAvoidBottomInset: true; reversed ListView so the latest message sits right above the composer. On focus, after the keyboard animation (~300 ms), jump to latest only if already near it. Android Enter inserts a newline; Send is the button (Ctrl+Enter on hardware keyboards).
Safe areas. Edge-to-edge with transparent system bars. Composer, bottom nav and sheets sit inside SafeArea(bottom); the chat list pads for the gesture inset so the last line is never under the handle.
Touch targets. 48 dp for primary actions and icon buttons; 44 dp minimum for inline actions (Rewrite, Copy, version arrows, chips, swatches). Visual size can be smaller; the hit area can't.

​

Long replies on small screens. AI text is full-width prose, not a bubble; 16 dp side padding at 360 dp wide; paragraphs 12 dp apart; actions in italic muted, dialogue brightest. Only the latest reply shows its action row, so long histories stay quiet.
Reading settings. One “Text & reading” sheet, opened from ⋯ in either mode: size (chat 14–22, default 16; story 15–26, default 19), line spacing Compact / Comfortable / Roomy, a live preview line, and narration and pacing in Story mode. Stored per device; respects the system text scale on top.
Portraits with fallback. CharacterAvatar always paints the tile colour + initial first, then fades in the image (150 ms) when it loads. On error it keeps the initial and doesn't retry until the next launch. The editor treats a picture as optional, and the colour doubles as the fallback.
Simple creation. Name is the only required field. “More details” stays collapsed by default. Leaving with changes opens Save draft / Keep editing / Discard (PopScope handles Android back too).
Relationship notes. Optional and subtle: one muted line under the message that caused a change (Chat), or a centred italic line (Story). Never numbers; “Hidden” turns them off. The journal is one tap from the chat ⋯ menu, the Story header menu, or the character profile.
